# Pattern Walk + Pattern Studio

ARCH 540 Assignment 2 (UBC M.Arch). Two linked single-file web tools for cultural pattern work in Vancouver's Punjabi Market and Chinatown. No build step; open the HTML files directly or host on GitHub Pages (like Pocket Studio).

## Files
- `pattern-studio.html` — the main tool. Image → pattern (symmetry detector, colour-layer reading, shape tracing), Text → pattern, **Ombrae tiles** (reflected-light optical tiles), 2D pattern maker (tilings, Hankin star patterns, motif lattices), 3D panel with relief/emboss modes, light study, exports (SVG, DXF, STL, heightmap PNG, tile CSV, JSON). Engine `pattern-core.js` is inlined inside it; three.js r128 loads from cdnjs. Published at https://claude.ai/artifact/X9kjU9vH4RqwFcqBY7NKNW — republish to that URL, never a new one.
- `pattern-core.js` — standalone detector + pattern engine (UMD). `analyze(gray,w,h)` returns lattice, wallpaper group, scores or a stop reason; `makePattern`, `remix` (kaleidoscope under any of the 17 groups), `basisFor`.
- `pattern-walk-map.html` — Vancouver map (Leaflet from cdnjs, City open data embedded: shoreline, streets, buildings/parcels/addresses/trees around the two focus areas, public art, cultural spaces). Explore → Survey → Propose workflow, Google keyless embeds for Street View, opportunity cells, site brief, hand-off text.
- `pattern-walk-guide.html` — how to use both, updated workflow diagram, what to add next.
- `fig1…fig5` — mid-review diagrams.

## Ombrae tiles tab
A second way of making a panel, parallel to the cut pattern rather than part of it: `S.omb.on` switches `generate()` to `ombGenerate()`, which returns `{tiles, cols, rows}` instead of `holes`, and every downstream function (`render2D`, `renderOrtho`, `buildGeometryFrom`, `updateStats`, `svgText`, `dxfText`, `exportBundle`, `pinSVG`) branches on `G.omb`.
- **Which sun works.** The tonal range is `A = sin(tilt)·hypot(Lx,Ly)` — how far the sun is off the panel's own *face*, nothing to do with how low it is. A sun straight at the face (azimuth 0, low elevation) gives no range at all; one well round in azimuth, **or high overhead**, gives the most. An earlier version of this file and of the UI copy said a low sun was strongest, which is backwards; the QA `behaviour` group now pins it.
- **The model.** Each tile is a disc hinged on a diameter and tilted out of the face. With the tilt fixed, the hinge's plan angle θ sweeps the disc normal around a cone, so `n·L = sin α·R·sin(θ−φ) + cos α·Lz` — monotonic in θ over half a turn, which inverts exactly: `θ = φ + asin(2t−1)` for a target tone t. That is why tones are solved for **one** design sun (`omb.designAz/El`) and wash out as the live sun moves; the washout is the effect, not a bug, and `ombStats()` reports how far off the design light you are.
- **Sources** all end as one luminance raster in `OMB.lum` (built by `ombField`): image upload, the photo already loaded in Image → pattern, lettering (`ombLetter`), six built-ins (`ombBuiltin`), or a text prompt that asks `sample` for a greyscale SVG which `ombCleanSVG` strips (script / image / foreignObject / on\* / external href) before `ombFromSVG` rasterises it. No model in the view → `ombKeyword` picks a built-in from the words.
- **Dimensions** are reconstructed from KPS's published figures (Ø12.7 / 25.4 mm, 31.75 mm pitch, 30°, 3 mm proud), not from their process. Ombrae™ / OpticalTile™ / Sculptural Imaging™ are Ombrae Studios + KPS marks; the attribution is in the tab, the README and this file, and must stay in all three.
- **The deliverable is `-tiles.csv`** — one row per tile (x, y, hinge angle, tilt, tone). The DXF/SVG/STL are for reading; the CSV is what a CNC setup or the Grasshopper direction would be driven from.
- `omb.field` in the design JSON is the tone raster as a ≤256 px PNG data URL, so a saved design reloads its image (~19 KB).
- Tile count is capped at 24,000 with a warning; `omb.seg` (3D facets) is the control that makes the 3D view heavy.
- `OMB_BUILTIN` is eleven designs, the first a real photograph (five pictures grounded in real Ombrae subjects, three abstract, two calibration charts) and `OMB_PRESETS` is eight complete worked panels. The maple leaf is an explicit outline, not a polar function — every procedural attempt gave slivers or a blob. Clouds need six noise octaves; fewer and the mask cuts straight diagonal edges that read as broken glass.

## Perforated image tab
A third panel kind, sharing the tile panel's tone field (`OMB.lum`) but encoding it as hole
**diameter** rather than tile rotation. `S.perf.on` switches `generate()` to `perfGenerate()`,
which returns the ordinary `{holes, open, W, H}` shape plus a `perf` metadata block — so
`render2D`, `buildGeometryFrom`, the DXF/SVG/STL exporters and `finish()`-free stats all work
with no branching beyond the backing colour and the stats line. That was the design choice
that made it cheap: a perforated image IS a cut panel, just one whose openings are computed
rather than tiled.
- **The two fabrication rules** are a hole no narrower than the sheet is thick, and a web
  (ligament between holes) no thinner than that either. `perfDesc()` warns on both. `maxD` is
  clamped to `pitch - minWeb` and to `rowPitch*pitch - minWeb` inside `perfGenerate`.
- **Slot length must be bounded by the row spacing** (`Math.min(d*aspect, rp-web)/2`). Without
  that bound slots overlap their neighbours and the reported open area climbs past 100%. The
  `perforated` QA group caught exactly that.
- `S.omb.on` and `S.perf.on` are mutually exclusive; each checkbox clears the other.
- Over 7,000 holes the 3D view builds the blank sheet and says so — extruding twenty thousand
  holes costs a minute and tells you nothing the 2D drawing doesn't.
- The photographic built-in (`gondola`, a 384 px greyscale JPEG as a data URL, ~41 KB base64)
  decodes asynchronously. `photoEl()` is called for every entry in `PHOTO_SRC` **at load**, and
  the branch falls back to mid-grey rather than black, because a lazily-created image meant the
  first build after picking it came out empty. Both the QA `perforated` group and the live tool
  hit that.
- Zahner call theirs ImageWall, Imark call theirs Ocular; this is an independent reconstruction
  of the principle and says so in the tab, the export README and here.

## Fields and brick courses (next phase, 30 Oct 2026)
- **Fields** (`S.field`, `FIELD_KINDS`, `fieldValue(F,u,v,W,H)` with u right and v UP, 1 = light). `ombFieldCanvas()` rasterises the field into the same tone canvas a photograph uses (`OMB.kind='field'`), alone or `multiply/add/mask` over `OMB.picEl`, the picture it replaced; `ombDrawField()` regenerates it instead of refitting when `OMB.kind==='field'`. `fieldUse()` is the single entry (sets `S.omb.src='field:<kind>'`). The cut pattern reads it through `grad.dir='field'` in `finish()` and `reliefHeights()`. Snapshots do NOT save a thumbnail raster for a field design; `applyPreset` rebuilds it from `S.field`. The sun field weighs each quarter hour by cos(el)·cos(az off the normal) and normalises to the face's own sunlight, so a flat face with no overhang reads 1 everywhere; in June at 49° a 600 mm overhang shades the top half of a south face all day, which is right.
- **Brick courses** (`S.brick`, `brickGenerate()` → `{bricks:[{x,y,i,r,len,theta,shift,t}],brick:{…}}`, flagged by `G.brick` the way `G.perf` flags the perforated panel). Running bond closes odd courses with two half bricks (`len`). The bearing rule: a brick may stand out `maxOver × bW`; a turned brick's corner stands out `len/2·sin θ` plus its offset, so θ is clamped and `brick.clamped` counts it. `renderBrick2D` is the shaded elevation, `renderBrickOrtho` the course drawing (red = apparent width `len·cosθ + bW·|sinθ|`, green = turn or offset), `brickGeometry` one `BoxGeometry` per brick merged, `brickCSV` the placement list, `brickSVGText`/`brickDXFText` the drawings. Modes are exclusive: `setPanelMode('brick')` switches the material to `brick` (a `Cast & stone` entry whose gauges are brick widths) and sets `S.thickness = bW`. The picture block (and the Field picker) is shared through `PIC_HOSTS.brick`. A UI `const` must not share a name with a function (`brickTones` vs `brickTone`): the page fails to boot with no message in run-qa; capture it with Chrome `--enable-logging=stderr` on `qa/_build/qa.html` (`--keep`).
- **Serial sections** (`S.serial`, `serialGenerate()` → `{ribs:[{i,c,a0,len,N,v,lo,hi,area,comp}],serial:{…}}`, flagged by `G.serial`). `v` is a Float32Array of depths (op contour) or angles in degrees (op twist) at N+1 stations along the rib; `c` is the rib's position across the panel, `a0` where it starts along. Horizontal ribs run along x at y = c; vertical along y at x = c. **Zero waste** (`zeroWaste`, contour only): rib 2k+1 is `stripW − rib 2k` with `stripW = dMin + dMax`, so a pair is cut from one strip with one line; `comp` marks the complement. `serialNest()` lays strips across the short side of the sheet and pieces end to end along the long side; a rib longer than the sheet is cut in `splice` pieces. `serialNestSVG`/`renderSerialOrtho` draw it (blue sheet and strip, red cut, green label); `serialSVGText`/`serialDXFText` export it (SHEETS / STRIPS / CUTS / LABELS, DXF TEXT entities); `serialCSV` is the schedule with the whole profile per row. 3D: contour ribs are an extruded Shape per rib (horizontal: rotateX(π/2) then translate to y = c + t; vertical: rotateY(−π/2) then translate to x = c + t); twist bands are a ribbon BufferGeometry between the hinge line and the swung tip, both windings. The mode sets `S.material` to `ply` unless it is already timber or sheet metal, and `S.thickness = t`. A field over a spanning set is sampled per panel slice, so a probe that wants the whole tone range on one panel must set `S.arr='single'` first (the twist check tripped on this).
- **Kinetic units** (`S.kin`, `kinGenerate()` → `{units:[{x,y,i,j,u,v,s,duty,stroke}],kin:{…}}`, flagged by `G.kin`). `kinStateAt(K,u,v,t,W,H)` is the whole rule: resting state from the tone, then the motion: `sun` uses `sunAt(lat,month,hour)` (hour = dayFrom + t·(dayTo − dayFrom)) and deploys by cos(azimuth off the face normal), gated by elevation; `walk` moves a point from `walkFrom` to `walkTo` with t and lights units within `reach`; `pulse` is a lagged sine. `blend` says how the picture and the motion combine (max / mul / add). The table (`kinCSV`) re-evaluates every unit at every step, so `steps` sets its width. 3D: a frame of four bars per unit plus petals (triangles hinged on the rim whose tip reaches the centre at s = 1 and lifts off the face as they fold), an iris disc, or a louvre flap turned (1 − s)·90°. Defaults pitch 300 / unit 270; a 900 mm panel at the old 600 pitch gave one column, which is how the walker test first failed.
- **Pavers** (`S.paver`, `paverGenerate()` -> `{pavers:[{pts,cx,cy,cut,area,t,type}],paver:{counts,cuts,areas,palette,heights,dropped,conflicts,pairs}}`, flagged by `G.paver`). `paverCells(P,W0,H0)` builds every layout in pattern space with the origin at the frame's corner (so at spin 0 a 300 mm grid starts with a whole paver at the corner), rotated by `spin` about that corner and clipped with the tool's `clipRect`; pieces under `minPiece` of a paver are dropped and counted. Herringbone is the lattice (w,-w), (L,L) with a horizontal paver at each lattice point and a vertical one at its right-hand end, checked numerically for 2:1, 3:1 and 4:1 before it went in. Cairo pavers are grown by quarter turns about the two right-angle corners, de-duplicated by centroids snapped within 0.3 mm. Voronoi: `paverSites` (jittered grid, or a Poisson disk whose radius follows the tone) then `voronoiCells` (the frame clipped by bisectors nearest first, stopping at the security radius). `paverNeighbours` finds pavers sharing a stretch of edge (collinear overlap, so running bond and herringbone neighbours count). Types: each type's level is its colour's luminance normalised across the palette; quantise = nearest level, dither = error diffusion over the neighbour graph in reading order, scatter = jittered tone; `apart` re-types a paver that matches a neighbour already laid. 3D: one extruded shape per paver at its type's height with a per-vertex colour; `makeMaterialFor` turns on `vertexColors` for `G.paver`. `paverCSV`, `paverScheduleCSV(list)`, `paverSVGText` (a group per type), `paverDXFText` (TYPE_n layers). The mode takes concrete unless the material is already Cast & stone; `S.thickness` = the tallest type. QA group `paver`, 7 checks (all eleven layout cases cover the frame once, by area and by point sampling).

- The catalogue (`catalogue/`) is the source of truth for what a system is; each card's `pattern_studio.status` says how much of it the tool does.

## Testing
`python qa/run-qa.py` builds a throwaway copy of the tool with `qa/harness.js` injected, runs it in headless Chrome and writes `qa/report.md` + `qa/report.json`. 341 checks in twenty-two groups, ~70 s. `--group <name>` filters what *runs*, not just what is reported. Exit 0 pass, 1 fail, 2 would not boot. The `pattern-studio-qa` subagent (`.claude/agents/`) runs it and explains the failures.
`python qa/run-prompts.py` is the second bench (42 briefs): every brief in `qa/prompts.json` through `heuristic()` → `validateProposal()`, checked against what the words say it should produce. It runs the **keyword** path, which is what a reader without Claude access gets, so it is a floor rather than a proof of the prompt. The `pattern-studio-prompts` subagent owns it and is allowed to fix `heuristic()`. Adding a bench case is cheaper than arguing about whether a brief was read right — the first run of it found nine real gaps (unknown materials, unknown motifs, no size parsing, a motif name read as a picture).
The one rule in `heuristic()` that keeps breaking is **ordering**: it is a cascade of `if`s and the last one wins, so `stainless` must precede `steel`, `basket weave` must follow `weave`, and `motifRe` must beat `subjectRe` or "a fern-leaf screen" becomes a photograph.
Three things cost hours to rediscover, so they are written down:
- `--dump-dom` needs `pathlib.Path(p).as_uri()`; the repo path has spaces and `!!` in it and an unencoded `file:///` URL silently dumps nothing.
- The suite must yield between cases (`setTimeout(drain,1)`). One long synchronous block starves the message loop and headless never gets round to dumping.
- `performance.now()` is frozen under `--virtual-time-budget`, so in-page timings all read 0 ms. Time from outside the browser.
- Headless Chrome on this machine often never exits after `--dump-dom` has written the page. `run-qa.py` therefore watches the dump file for the `RESULT` title and the closing `</html>` and kills the browser itself; `QA_EXTRA=<seconds>` adds wall-clock allowance per group. Any new headless driver must do the same, or a finished run looks like a 30-minute hang.
Metrics worth knowing: **fidelity** is the correlation between the tone each tile was asked for and the tone it actually returns under the design light — it tests the solve and the renderer agree, not whether the picture is nice. **toneSpread** is how much of black-to-white the design uses. **dial** is the range of the tone strip at the current design light; under ~0.18 the panel cannot hold a picture.

## Grasshopper
`grasshopper/` has two GhPython components and a README. `ombrae_from_image.py` does the whole job in GH; `ombrae_from_csv.py` rebuilds a panel from the `-tiles.csv` the web tool exports, so the two can be checked against each other. Written for IronPython 2.7 and CPython 3 both: no f-strings, `System.Drawing` for the image. `ombrae_from_image.gh` is that component wired up in Rhino 8 (Python 3 Script, inputs on the "Any" hint). Oct 2026, driven via the Rhino MCP: `ombrae_from_image.py` solves cleanly (3,308 tiles at defaults, solid ≈ 4.7 s) and reads an image the right way up (black disc → tone 0.01 inside, 0.99 outside). Still never run: `ombrae_from_csv.py`, the browser-vs-Rhino tile-for-tile check, IronPython 2, and a visual check in the viewport — say so in anything said about them.

## Navigation and state
- **The tab is the mode.** `TAB_MODE` maps Pattern / Ombrae tiles / Perforated image to cut /
  tiles / perf; `showTab(name, byUser)` calls `setPanelMode` only on a user click, so programmatic
  `showTab` (presets, the tour) never flips the mode behind someone's back. `orderTabs()` puts
  the rail in `TAB_ORDER` regardless of build order, which is why Pattern sits above the two
  picture tabs although its code is built after them.
- **What is read travels.** `carrySource()` runs after a successful `srcAnalyze`: the image
  becomes `OMB.srcEl` (so Ombrae and Perforated carry it) and the classic pattern of the detected
  group goes into `S.pattern`. Switching tabs then shows the same thing built three ways.
- **Panel size & arrangement is built three times** (`panelSetup(parent)`, one per panel tab)
  over one state; `EL_DYNS[]` holds each copy's dynamic rows so `buildElementDyn()` rebuilds all
  of them. Composition is a fold inside Pattern (`compHost`), not a tab.
- **Undo/redo** is snapshot-based: `historyPush()` runs at the end of `run()`, keys entries on
  the snapshot minus the tone-field data URL, collapses pushes within 700 ms (a slider drag is
  one step), and `HIST.skip` suppresses the push that an undo itself causes. `restoreDesign(p)`
  is `applyPreset` plus the two things it does not carry: which panel kind was on, and a picture
  for a perforated design. `snapshot()` now saves the field when either picture mode is on.
- **Bank** reuses the `pins` array (name, when, snapshot, thumbnail) and localStorage key
  `ps-pins`; `exportBank()` rebuilds each design in turn — awaiting the field image first — and
  restores the studio afterwards. Perf designs over 2,500 holes render in 3D as a `BoxGeometry`
  plate wearing the holes as a `CanvasTexture` alphaMap (`perfAlphaCanvas`), with a
  `customDepthMaterial` so the shadow pass knows about the holes; that is also what lets the
  backlit plane show through.
- **Tour** (`TOUR[]`, `window.PS_TOUR`) is the single source for the Demo button and for
  `qa/record-demo.py`. Seventeen steps: guide (opens the welcome card), read, describe, pattern, set (Across the set + orthographic One/All/Panel n of N), photograph as halftone cut, tiles, perforated, material, light,
  bank, export (the pattern step clicks `#srcClassic` so the classic screen of the read group is what shows).
  The film is 26 stills held 3.8-5 s by caption length, crossfaded, about 108 s. Since pass 18 every tab's `How to use this tab` steps and its long
  explanation are ONE help fold at the foot of the tab, opened by the `?` button by the title (the lede is `LEDE[name]`). The proposal readback tables are `table-layout:fixed`
  with wrapping cells; QA `layout` proposes a brief and fails if the readback is wider than the rail. Step 3 cannot call the model headlessly, so a recording shows the keyword
  reader's built-in picture and the caption says so; the live artifact draws from the words.
- **Spanning picture.** `S.omb.span` + `spanOn()` (needs tiles or perf and a non-single arrangement). The tone
  field is rasterised at `fieldW()×fieldH()` (the whole array, joints included; canvas cap 1400 px); `generate()`
  loops the panels with `OMB.sp={ox,oy,TW,TH}` and `uvFor()` maps a panel-local point into the field; the result
  is panel 0 plus `G.panels[k]` (k = col*rows + row, row 0 at the bottom), `G.span`, `G.total`. 2D renders, ortho,
  `rebuildScene` (one geometry + material per panel, `mesh.userData.Gk`), `updateMaterial` and `exportBundle`
  (files per panel, `-c1-r1`) all read `G.panels`. `span` defaults to TRUE (a photo on several panels is one picture); `applyPreset` restores that default unless the preset says `span:false` (the flower spandrel does).
  Built-in photo `skyline` and the two **North Shore skyline · six panels** presets are the test case; QA covers it
  in `perforated` and `tile-designs`.
- **Stand-ins.** `standInFor(txt)` picks the built-in that stands in for a described scene when no
  model is in the page (gondola, ridge before wave with forest words, flower, clouds only for cloud/sky/rain, rings, ramp,
  else `facets`). Both `heuristic()` image chains and both Accept placeholders use it; nothing
  defaults to the cloud bank any more. `WAVES_BRIEF` is the second worked brief (perforated, backlit).
- **Framing.** `S.omb.zoom/fx/fy` enlarge the fitted source about a focus point in `ombDrawSource`;
  `fitKeyNow()` is the raster cache key (size, fit, zoom, focus). Controls live in a `Framing` fold under
  the picture in both panel tabs. The tour's perforated step sets zoom 1.8 at (.46,.4) to frame the cabin.
- The Agent tool in a running session only knows the agent types loaded at start-up, so the
  cron prompts say `subagent_type "general-purpose"` and have the agent **read its own
  definition file first**. A fresh Claude Code session can call the five agents by name.

## Panel hierarchy
Each of the three panel tabs is built into named host `div`s created up front in design order
(`ombLead, ombPic, ombPanelHost, ombTiles, ombToneHost, ombSun, ombWorked, ombDialHost, ombAbout`
and the `perf*` equivalents), so source order no longer dictates screen order and a control can
be moved by changing one host name. `segc()` is a segmented control bound to state, `stepper()`
a minus/plus count, and every checkbox is styled as a switch; `buildPatternParams` renders a
select with three or fewer options as a segment. The Ombrae picture chooser is a four-way picker
(built-in / upload / lettering / describe) showing one block at a time over the same element ids,
with the fit select kept hidden so presets and the fit segment stay in sync.
**Backing in 3D:** with a perforated backing the room's own `wall` mesh is resized to the panel
and moved to `-(t+60)` with `wallGlow` (unlit) or `wallColour`; without one it goes back to
`light.wall` and `wallSurf`. Overhead panels keep an in-group plane because they have no wall.
Backlit, or the **Night** time-of-day chip (`S.light.night`), drives `night` in `updateLights`: sun x0.03,
lamp x0.22, hemi <= 0.025, camera fill 0.02, near-black floor and background. Night switches to the lamp.
Bank entries carry `pinned`; the strip shows only pinned ones, the Bank tab all of them. Unpin never
deletes; delete lives behind *Edit the bank*. QA group `layout` opens every fold in every tab and
arrangement at a 1500 px window and fails if anything is wider than the rail.
The tour card docks over the control column (`.tour` right:134px) so it never covers a viewport.
**Recording 3D frames headless:** under `--virtual-time-budget` the compositor presents a WebGL frame only
sometimes. `PS_TOUR.freeze()` renders synchronously, copies the drawing buffer with `toDataURL` in the same task
and lays it over the canvas as an `<img>` (id `psFreeze`); `PS_TOUR.gl()` reports context loss and draw calls.
`window.__PS_COARSE` (set by the recorder for frames after the tile step) makes the tour's tile step coarse and
skips its sun sweep. The recorder uses a fresh Chrome profile per frame: Chrome remembers GPU crashes per profile.
The film is sixteen stills, each a 3 s clip with a slow push-in (ffmpeg `zoompan`), crossfaded 0.5 s (`xfade`),
encoded crf 27 to stay under the artifact host's 15 MB file limit; `--video-only` rebuilds it from `review/frames/`.
Perforated plates in 3D use a 3072 px alpha map with blended transparency (alphaTest .04), so from a distance a
field of small holes reads as tone and a backlit sheet glows where the picture is light.

## UI density
The control panel is folded: each tab shows the five or six controls that are decisions, and
everything else sits in a `details.grp` collapsible built by `group(parent,title,hint,open)`.
The **Essentials / Everything** segment in the header opens or closes all of them at once
(`GROUPS[]`). **Panel mode** (through cut / emboss / carve / terrace) is the first control in
the Pattern tab, not buried in 3D panel, because it decides what everything under it means.
Thickness lives in **Material**, as a chip row of the stock gauges that material is rolled in,
because thickness is a property of the stock and not of the geometry.
Both viewports have a **Save image** button; `viewPNG('2d')` serialises the stage SVG, resolves
the theme's CSS variables into it, and redraws it into a canvas at 2x. `S` / `Shift+S` do the
same from the keyboard.

## Conventions
- Single self-contained HTML files; all CSS/JS inline except the two CDN libraries. Keep it that way so GitHub Pages works with no tooling.
- Fonts: Instrument Sans + DM Mono (Google Fonts). Palette tokens live in the `:root` block of each file; both light and dark are defined.
- Units are millimetres everywhere in Pattern Studio. DXF layers: OUTLINE / OPENINGS (through cuts) and CUTS / SLOT_CENTRELINES (map tool).
- Everything the detector or the text model produces is a proposal; UI copy must say so and the rule card / provenance record must travel with exports.
- Test in headless Chromium (Playwright). The three.js and Leaflet CDNs may be blocked in sandboxes; inline the library from `npm pack` into a test copy when that happens.

## Known limits / next steps
- Detector tuned on synthetic Gaussian-blob patterns (42/44) and now also passes all 17 crisp `SAMPLES` test cases; still not validated on real storefront or textile photos. Shape classifier is rule-based (circularity, solidity, lobes, aspect) and coarse at small repeats.
- Colour reading: k-means palette (≤6), per-layer tracing; the lattice from the whole image is reused for layer reads.
- Ombrae reflectance is Lambert + a Blinn highlight with a frontal viewer in 2D; it is not a measured BRDF for brushed or anodised aluminium, and inter-tile shadowing and bounce are ignored (the 3D view does cast real shadows). The 30° tilt and 3 mm standoff are read off a brochure section, so treat them as plausible, not verified.
- Not built: vector trace of a full motif into editable curves, Parakeet genotypes, irregular tilings, Rhino/Grasshopper live preview, the Grasshopper definition that would drive a real tile panel from `-tiles.csv`, a viewing-angle control for the 2D tile simulation (the 3D view stands in for it), Claude-vision worded description beside the geometric reading (artifact `sample` capability with images), the Punjabi Market motif library from user sessions.
- Dates: user match by Nov 6, peer reviews Nov 13/17 and Nov 27, final live review Dec 10.
